# 开源与安全边界

公开代码不等于开放作者的服务器。此仓库没有默认公共 relay；用户部署自己的实例。

## 私密数据

不得发布 config/state、完整 DR2、Bearer/E2E key、Redis/Vercel token、二维码、聊天记录、签名私钥、真实环境变量、已填本机路径的启动器。`.runtime.env` 是受信任 shell 配置，只能由本机用户编辑。

公网域名并非密码，但属于部署配置，公共示例使用占位值。页面托管方能够修改客户端代码，因此 E2EE 仍依赖网页/APK 可信与无 XSS，不保证恶意客户端托管者无法接触密钥。

## 发布检查

`node scripts/audit-public.mjs` 检查待发布的 tracked/非忽略文件；若本机有 config，还会在内存中比对实际凭证和网址，只输出命中文件名，不输出敏感值。它不是完整通用 secret scanner。

`node scripts/audit-public.mjs --history` 额外检查可达 Git 历史。老提交中存在硬编码的个人地址/路径不等于密钥泄露，但不应直接把未经审计历史推到公开仓库。若要删除历史或换许可证，先明确用户选择；当前任务不会擅自 force-push、删除历史或选择许可证。

正式发布前还应使用专门 secret scanner（脱敏输出）、核查依赖许可、选择 LICENSE、检查 APK/截图/CI 日志。`.gitignore` 不会删除已经提交的秘密。

在 Git 工作树中运行 `node scripts/export-public.mjs`，先执行工作树检查，再导出 `dist/dsh-suite-v<version>-source.tar.gz`；包含当前修改后的公共源码，不包含 `.git` 历史或被忽略的配置/产物。导出包可直接测试和构建，重新审计/导出需先建立自己的 Git 仓库。它不代替最终许可证与安全审查。

桌面私有配置 `desktop.settings.json`、套件的用户级配置、DSH 自己的登录凭据不随源码导出。Windows 原生消息桥仅接受配置的本机 DSH origin；远程网页不会获得读取余额/配对码的原生权限。DR2 只在用户主动选择原生菜单后显示，不注入网页。

## 保留与权限

服务端只保存密文与元数据；DR2 持有者拥有整个通道权限，当前无单设备撤销。CORS 不是认证，非浏览器可以不发送 Origin。

Stream 近似保留每方向 2000 条；客户端拒绝超过 30 天的密文，不代表服务器在 30 天自动删除。网络重试与有限去重不是严格 exactly-once，敏感命令仍需 DSH 的审批策略。

Android 产物目前为 debug 签名构建。公共正式发布需单独管理签名密钥；同包名不同签名不能直接覆盖安装，不能为修复安装错误要求用户先删除旧数据而不说明后果。
